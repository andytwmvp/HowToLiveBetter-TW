# 歷史臺灣內容回溯審查｜查核規範與紀錄入口

本文件說明如何重新核對既有內容及在哪裡查看證據，不逐批刊載工作摘要。各篇正文、來源、審閱狀態和統計判斷均以結構化追蹤資料為準。

## 正式紀錄

- `retroactive-review-register-20261019.json`：逐條記錄歷史再審日期、正文前後 SHA、來源 ID、台灣情境、頻率判斷、未解事項和複查期限。
- `reviews/TW-*.json`：記錄各條目的來源主張對應、查閱方法、審閱範圍與專業審閱限制。
- `tw-edition/runtime.json`：供網站、自我檢視、Skill 和離線輸出共用的正式閱讀內容及已核對來源。
- `tw-edition/coverage.json`：最新核心完成狀態、未核對稿件、未起稿主題與來源缺口。
- `localization/` 內的批次 JSON：保留原始研究或官方資料的讀取方式、統計範圍和完整來源證據；不把這些工作紀錄輸出成讀者正文。

## 再審原則

1. 依可能造成的傷害、行動時效和制度影響安排順序；排序不是事件發生率或個人風險排名。
2. 逐條確認台灣生活情境、法律與制度、來源效期、統計定義及分子分母。案件數、就醫人次、事故數、死亡數和個人機率分開處理。
3. 找不到可信且適用的台灣統計時，記錄「資料不足」及搜尋界線，不自行估算；低頻或無統計也不會改變法律禁止或重大傷害的處置優先度。
4. 來源須直接支持對應主張。官方首頁只作服務入口，不代替法規、公告、統計表或正式申請說明。
5. 正文有實質變更時，同步 runtime、逐篇 review、manifest 和前後 SHA；若只調整讀者用語，保留原來源審查結論並清楚區分。
6. 將 AI 輔助來源核對和專業審閱分開記錄。沒有取得專業審閱時如實保留限制，不因測試或審閱狀態欄位而宣稱具備出版條件。

## 動態驗收

在儲存庫根目錄執行 `python3 tools/tw/retroactive_audit.py --check --report /tmp/retroactive-audit.json`。報告是動態產物，應放在暫存位置，不提交到版本控制；必要驗收以儲存庫工作流程及最新 GitHub Actions 結果為準。
